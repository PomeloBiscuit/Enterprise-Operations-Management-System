Enterprise Operations Management System

A PHP 8 and SQLite demonstration system for everyday enterprise operations.

System Overview

This management system covers everyday enterprise operations: employees, customers, products, orders, shipments, order invoices, and vendor-customer relationships, with create, read, update, and delete operations. The whole database is a single SQLite file; there is no database server or database credential to configure. One docker compose up -d command runs it locally with seed data.

The backend is plain PHP 8, with no framework, Composer, or build step. The frontend uses Bootstrap 4.3.1 and jQuery. The project includes a repeatable verification script covering 42 checks.

System Architecture

Every request passes through the single front controller index.php, whose ?Act=<number> URL parameter determines which page to include. Permissions have three layers: the route allowlist in index.php, named guards in auth.inc.php, and a guard inside every page. Query values use PDO prepared statements; field names and sort direction are mapped to fixed strings by a server-side allowlist.

Two Notable Design Decisions

  • User and admin have no foreign keys and are unrelated to other tables. admin is the master data for vendors and customers, not a user table; it reuses part of User's naming but has a different purpose.
  • orderandinvoice.order_number and customer_name are read-only snapshots taken when an invoice is issued, not redundant fields. If a customer later changes name, an old invoice still shows the issued name. The relationship truth remains in the order_id and customer_id foreign keys, whose RESTRICT deletion behavior prevents deleting an order or customer from orphaning an invoice.
SQLite foreign-key enforcement is off by default and must be enabled on every connection. This project runs PRAGMA foreign_keys = ON immediately after each PDO connection; otherwise ON DELETE CASCADE silently stops working.

Permission Model

A role is represented by the integer User.limited field; roles are not compared by magnitude. A new role must be explicitly added to the corresponding allowlist in auth.inc.php.

limitedRoleAccessible scope
0UnauthorizedNone (the default after registration or after disabling)
1AdministratorEverything, including user management
2Internal employeeProfile plus all business data
3External user (vendor or customer)Profile only
Named guardCondition to pass
is_logged_in()limited is set (logged in)
is_admin() / can_manage_users()limited == 1
can_view_business_data()limited is 1 or 2
can_access_self()limited is 1, 2, or 3

Passwords use PHP's built-in password_hash() (bcrypt, with the $2y$ prefix and length 60). An external user selects a party_type (vendor or customer) at registration; their limited value is always 3 after registration.

Run It Locally

Docker (One Command)

Prerequisite: Docker Desktop.

git clone https://github.com/PomeloBiscuit/Enterprise-Operations-Management-System.git
cd Enterprise-Operations-Management-System
docker compose up -d

When the container starts, it copies config.inc.php from the example file and runs create.php once, so the application opens with seed data.

  • Application: http://localhost:8080/login.php — sign in as Admin / 123456

Rebuild the database at any time (repeatable; it rebuilds tables and seed data each time):

docker compose exec web php scripts/create.php
create.php is in scripts/, outside the DocumentRoot. It cannot be run from a browser, so no one can clear the database merely by visiting a URL.

Without Docker

PHP 8 with the pdo_sqlite extension is required (it is built in by default). The DocumentRoot is public/:

cp src/config.inc.php.example src/config.inc.php
php scripts/create.php              # Create the database and seed data
php -S localhost:8080 -t public     # Then open http://localhost:8080/login.php

Five-Minute Tour

After signing in as Admin / 123456, these four steps show what the project is designed to demonstrate:

  1. Order list (navigation bar → order list): every row has an item count and order amount. The amount is not stored on the order; it is calculated live by SUM(Contain.Quantity × Product.UnitPrice). An order can contain many products, each with a quantity.
  2. Add an order: the product area can add multiple product-and-quantity rows. This is the practical operation of the Contain M:N relationship table—the diamond in the ER diagram.
  3. Register a vendor account and sign in with it: customers, employees, orders, and invoices all show “Permission denied”; only the profile remains. Permissions are not based on numeric order: a new role inherits nothing and must be explicitly added to the allowlist in src/auth.inc.php.
  4. Run the verification script (about 20 seconds): docker compose exec web bash scripts/smoke.sh. Its 42 checks cover schema, foreign-key cascading, time zones, sign-in, password hashing, SQL-injection probes, permission boundaries, direct-access protection, and order-total accuracy.
Incidentally, directly opening http://localhost:8080/src/pages/customer/CustomerAdd.php returns 404: every page file is outside the DocumentRoot. Only the four public entry points—index.php, login.php, logout.php, and register.php—are exposed.

How to Verify It Is Correct

The project includes a repeatable verification script covering 42 smoke checks; any failure exits with a non-zero status.

docker compose exec web bash scripts/smoke.sh
  • Database structure and seed data: exactly 9 tables; expected seed counts; PRAGMA foreign_keys is 1; ON DELETE CASCADE actually cascades (verified in a transaction and rolled back); PHP and SQLite time zones agree; clearing orderandinvoice resets the next sequence to 1; every invoice has foreign keys and non-empty snapshots.
  • Sign-in and passwords: Admin / 123456 can sign in and receives PHPSESSID; wrong passwords are rejected; the Admin hash starts $2y$ and has length 60.
  • Permissions and direct access: all 45 feature files use their required named guards; an external user is registered with limited=3, can sign in, and sees only the profile; every non-exempt .php file under the web root displays “Permission denied!” without application content when opened while unauthenticated.
  • Order totals: every order has Contain details; at least one has an item count ≥ 2; and the order amount rendered by OrderList.php over HTTP equals SUM(quantity × unit price) (omitting quantity would produce a different result, so the probe is discriminating).
  • Injection prevention, routes, and hygiene: an SQL-injection probe submits a field value containing '); DROP TABLE admin;--; the string is stored literally and the admin table remains intact; all 18 specified Act routes return 2xx/3xx with no PHP error; Apache output has no Deprecated, Warning, or Fatal; tracked Git files contain no *.sqlite, sess_*, config.inc.php, or *.mp3.
